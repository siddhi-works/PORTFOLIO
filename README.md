# Siddhi Kale: portfolio

welcome to my portfolio!

One long scrolling home page, a case-study page per featured project, a page per service, record pages
and a role-wise résumé page. Plain HTML, CSS and JS generated by a zero-dependency Node script, so there is
nothing to install.

```
content.mjs      all copy, links, projects, numbers (the one file you edit)
build.mjs        static site generator, writes ./dist
serve.mjs        build + local preview server
src/             site.css, site.js, visuals.js (copied to dist/assets)
media/           photo, résumé PDF, project screenshots (copied to dist/media)
vercel.json      build command, output folder, headers
```

## Run locally

```bash
node serve.mjs     # builds, then serves http://localhost:5173 (PORT=5190 node serve.mjs to change)
node build.mjs     # build only, writes ./dist
```

Add `?intro=0` to a URL to skip the laptop intro, or `?intro-frame=0.5` to freeze it at any moment (0 to 1).

## Deploy on Vercel

1. Push this folder to a GitHub repository.
2. On vercel.com choose **Add New, Project**, import the repository and press **Deploy**.
   No framework preset or environment variables are needed: `vercel.json` sets the build command
   (`node build.mjs`) and the output folder (`dist`).
3. Set `site.url` in `content.mjs` to your final domain. It feeds the canonical links, the sitemap
   and the social preview image.

Every push to the main branch redeploys. `dist/` is generated on Vercel and is not committed.

## Edit content

Everything lives in `content.mjs`. Each project has these optional fields; anything left out is simply
not shown:

| Field | What it does |
| --- | --- |
| `page: true`, `top: true` | detail page, and featured on the first cards |
| `live`, `repo`, `post`, `demo`, `extra` | live app, GitHub repo, LinkedIn post, demo video, extra links |
| `builtFor`, `team`, `when` | the "Built for / Team / When" line on the project page |
| `study` | `problem`, `solution`, `build`, `result`: lists of paragraphs shown as boxes |
| `facts`, `flow`, `tools` | at-a-glance numbers, how-it-works steps, tech stack chips |
| `shot`, `gallery` | card and page screenshot, plus extra screens |

Lines marked `CONFIRM` need a check. `showSlotHints: true` shows marked placeholders for missing files.

## Opening sequence and music

After the laptop intro the site plays a short cinematic: the avatar clip (`media/intro/avatar.webm`, transparent WebM)
with the name in 3D layers behind it, then the name flies to the hero and the portrait assembles pixel by pixel.
`media/intro/theme.mp3` plays across the site (ducked while the avatar speaks, faint after) with a toggle in the top bar.
Sound effects are synthesised in `src/cinema.js`, so there are no extra files.

- The site loads straight into the laptop intro. Browsers only allow sound after a click, so if autoplay is blocked a small "Click anywhere for sound" chip appears and the music and avatar voice start on the first click or key press.
- Replace the two files in `media/intro/` to change the clip or the track. Keep the clip as a transparent WebM (VP9 with alpha).
- It plays once per session and is skipped with reduced motion.
- Captions: paste the exact words spoken in the clip into `intro.speech` in `content.mjs`. They type out in quotes on the left and right of the avatar, timed between `speechStart` and `speechEnd` (seconds). Leave it empty for no captions.

## Accessibility and motion

- `prefers-reduced-motion` turns off the intro, page transitions, floating motion and streaming text.
- The intro plays once per session and has a Skip button (Esc also skips).
- Projects sit side by side on a rail with arrow buttons. Keyboard, touch and mouse-drag all work.
  With reduced motion, clicking a card is a plain link.

## Phones and Android

The site is a normal responsive website, with no install step. On phones the project orbit becomes a 2x2 grid, tap targets are at least 44 px, and Android Chrome shows the address bar in the site's dark colour (the `theme-color` tag). There is no service worker, so every visit loads the latest deploy.

## Security, performance and search

- Every page carries a Content-Security-Policy (a `<meta>` tag built in `build.mjs`). It allows only this site's own files, Google Fonts, and the form endpoint's origin. If you add a new third-party script, font or image host, add it to the `CSP` list in `build.mjs`, or the browser will block it.
- `vercel.json` adds the other security headers (nosniff, referrer policy, frame protection, permissions policy).
- The avatar clip is about 7 MB. The cinematic intro is skipped on data saver or a 2G connection.
- Images get their width and height from the file at build time, so the page does not jump while they load.
- Meta descriptions are cut to 160 characters, and the 404 page is marked `noindex`.
- `site.url` in `content.mjs` must match the live domain. It feeds the canonical links, sitemap, robots.txt and social previews.

## Typography

**Sora** for headings, numbers and buttons, **Inter** for body text (so body copy never reads like a headline), and **JetBrains Mono** only for tech chips and terminal titles.
Weights: 400 and 500 for body, 600 to 800 for display. 
Sizes come from tokens at the end of `src/site.css` (`--t-micro` to `--t-h2`), so change a token to change every place that uses it.
